# Дорожная карта Makosh

Сравнение текущего монолита (см. `docs/architecture/current.md`) с персональным локальным агентом. Это план, не реализация. После каждого будущего шага процесс по-прежнему запускается командой `python -m makosh`.

## Статус

- M0 — выполнен.
- M1 — completed (29 сентября 2026). Детали ниже, в шаге M1.
- M2 и следующие шаги не начаты.

Цель сопровождения: один разработчик, один процесс, один SQLite, тот же HTTP/WS контракт. Новые возможности добавляются модулями рядом с `Agent`, а не новыми сервисами.

## Целевая архитектура

```
браузер ПК / ноутбука / телефона
            │  один WebSocket
            ▼
        makosh.hub          сеть, токен, статика, inbox
            │
        makosh.agent        цикл: собрать контекст → модель → инструменты → проверка
            │
     ┌──────┼──────────┬─────────────┐
     ▼      ▼          ▼             ▼
  llm.py  tools/   permissions   memory.py
  один    реестр   allow /       факты, реплики,
  OpenAI- и схемы  confirm /     журнал инструментов,
  клиент           deny          эпизоды
     │
     ▼
  этот ПК (инструменты в процессе)
  позже: сокет ноутбука, если инструмент должен выполниться там
```

Телефон остаётся тонким клиентом: текст, голос браузера, скачивание файла. Ноутбук сначала тоже клиент интерфейса. Отдельный узел на ноутбуке нужен только когда агент должен видеть экран ноутбука или запускать программу именно на нём. Логика задачи живёт в хабе на основном ПК.

`Agent` не импортирует конкретный класс DeepSeek. Он зависит от маленького протокола «сообщения + инструменты → ответ». DeepSeek API, OpenRouter, Groq, OpenAI и локальный сервер с тем же протоколом — это настройки `OPENAI_BASE_URL` и модели. Второй класс backend нужен лишь для канала, который не умеет этот протокол. Сейчас такой канал — гипотетический CDP к `chat.deepseek.com`, и его нет в коде.

## Что сознательно не добавлять

- Docker, Kubernetes, шина событий, очередь задач, вторая база.
- Микросервис на каждый инструмент или на каждое устройство.
- Векторная база на текущем объёме памяти.
- Пустые пакеты «на вырост» до шага, который их заполняет.
- Перепись `hub.py`, страницы и SQLite без изменения поведения на ранних шагах.
- CDP как основной способ вызывать модель.

## Agent Core: какие части реально нужны

Имена из постановки сопоставлены с кодом. Класс заводится только там, где текущий файл иначе придётся раздувать на каждом новом инструменте.

| Часть | Решение | Почему |
| --- | --- | --- |
| AgentCore | оставить класс `Agent` в `makosh/agent.py` | цикл из шести вызовов уже есть, это и есть ядро |
| ContextManager | не делать класс в P0 | сборка prompt — около пятнадцати строк в `handle`. Отдельная функция появится в P1, когда в контекст добавятся эпизоды и их нельзя будет вывалить целиком |
| Planner | отложить до P1 | сейчас планирует сама модель через tool calls. Отдельный план нужен, когда шаг надо пережить обрыв сокета и проверку |
| ToolRegistry | добавить в P0 | десять веток `if/elif` плюс параллельный список схем; новые инструменты иначе правят один и тот же цикл |
| TaskExecutor | не выделять в P0 | исполнитель — тот же цикл `handle`. Датакласс задачи появится вместе с подтверждением и проверкой |
| PermissionManager | добавить в P0 | политики нет вообще, а следующие инструменты разрушительны |
| Memory | расширять `makosh/memory.py` | факты и реплики уже в SQLite |
| ModelRouter | тонкий модуль `makosh/llm.py` в P0 | клиент OpenAI сейчас создаётся внутри `Agent`. Нужен шов, а не иерархия провайдеров |

P0 не строит конечный автомат. Он оставляет поведение beta и добавляет швы: реестр, каталог прав, протокол модели, структурный результат инструмента, живой сокет при ошибке модели, проверка хотя бы у `open_app`.

### Контракт модели

```text
complete(messages, tools, model) -> текст | список tool_calls
supports_vision() -> bool
supports_tools() -> bool
```

Единственная реализация P0 — нынешний `OpenAI` SDK и текущие переменные окружения. `supports_vision()` заменяет поиск подстроки `deepseek` в `agent._look_screen`. Для DeepSeek API метод возвращает false, пока у выбранной модели нет приёма изображений.

### Контракт результата инструмента

Внутри процесса, до превращения в строку для модели:

```text
ok: bool
tool: str
output: str
data: object | null
error: {code, message} | null
verified: bool | null
```

Модель по-прежнему получает текст. `verified: null` значит «этот инструмент ничего не проверял». `verified: false` значит «команда ушла, свидетельства цели нет». Ответ пользователю нельзя строить так, будто цель достигнута, если `verified` не true.

Коды ошибок, общие для инструментов: `bad_args`, `denied`, `needs_confirmation`, `not_found`, `timeout`, `failed`, `unverified`.

## Инструменты

Существующие имена (`remember`, `recall`, `list_devices`, `list_files`, `send_file`, `look_screen`, `open_app`, `open_path`, `type_text`, `press_hotkey`) сохраняются. Новые имена добавляются рядом, без переименования старых.

Уровень опасности:

- `none` — чтение, без подтверждения;
- `low` — обратимое локальное действие из белого списка, без подтверждения;
- `medium` — действие в фокусе пользователя или запись, подтверждение;
- `high` — удаление, оболочка, системные настройки, отправка сообщения, платёж, всегда подтверждение, часть команд запрещена насовсем.

Подтверждение в P0 только описывается и отклоняет ещё не существующие опасные инструменты. Текущие beta-инструменты не начинают спрашивать разрешение, иначе голосовой сценарий сломается до появления кнопок в интерфейсе.

### Уже есть

| Инструмент | Вход | Выход пользователю модели | Опасность | Подтверждение | Ошибки |
| --- | --- | --- | --- | --- | --- |
| `remember` | `key`, `value` | строка «Запомнил…» | none | нет | сбой SQLite → `failed` |
| `recall` | `query` | до 8 строк фактов | none | нет | пустая память — это `ok`, не ошибка |
| `list_devices` | пусто | текст реестра | none | нет | пустой список — `ok` |
| `list_files` | `path` | до 80 имён | none | нет | вне корней `denied`, нет пути `not_found` |
| `send_file` | `path`, `device` | куда легла копия | low | нет, пока устройство уже подключено пользователем | не файл `bad_args`, устройство не в сети — `ok` с inbox `unclaimed` |
| `look_screen` | `mode: ocr \| vision` | OCR и иногда описание кадра | none для ocr; vision тратит лимит | нет | лимит и запрет картинок — `ok` с текстом OCR, не падение |
| `open_app` | `name` | строка запуска | low для белого списка | нет | не из списка `denied` |

| `type_text` | `text` | «Напечатал текст» | medium по смыслу, сейчас фактически без спроса | не включать, пока нет UI подтверждения | сбой pyautogui `failed` |
| `press_hotkey` | `keys` | «Нажал…» | medium, если в сочетание входят `enter`, `delete` или `win` | отложить до UI | клавиша вне списка `denied` |

| `screenshot` | `monitor` (необязательно) | JPEG не уходит модели само по себе; наружу — путь превью, ширина, высота, изменился ли кадр относительно прошлого | none | нет | P1. Это захват без LLM. `look_screen` остаётся |

| `focus_window` | `title` | заголовок окна, которое стало активным | low | нет | P1 |

У `mouse` и `keyboard` ошибка `unverified`, если фокус или кадр после действия не совпали с ожиданием.

### Файлы

Корни по умолчанию остаются текущими на время P0, чтобы не сузить beta молча. Отдельный шаг P1 вводит явный список корней. Документированная цель продукта уже уже кода: Desktop, Downloads, Documents и `data/`. Домашний каталог целиком — слишком широкое чтение для агента.

| Инструмент | Вход | Выход | Опасность | Подтверждение | Когда |
| --- | --- | --- | --- | --- | --- |
| `read_file` | `path`, `max_bytes` (потолок в коде, например 200 КБ) | текст или пометка «бинарный / обрезан» | none | нет | P1 |
| `search_files` | `root`, `query`, `limit` | пути совпадений внутри корней | none | нет | P1 |
| `write_file` | `path`, `content`, `mode: create \| overwrite \| append` | путь, размер, был ли файл раньше | medium | да | P1, только после канала подтверждения |
| `delete_file` | `path` | путь и факт отсутствия после удаления | high | да | P1 |
| `delete_folder` | `path` | каталог отсутствует; отказ, если путь — корень диска или корень из allowlist | high | да | P1 |

Ошибки файлов: путь вне корней `denied`, каталог вместо файла `bad_args`, файл занят `failed`. Удаление проверяет отсутствие пути вторым вызовом, иначе `unverified`.

### Система

Без новой зависимости, если хватает стандартной библиотеки и уже разрешённых команд чтения (`Get-CimInstance`, `Get-Process` через узкий вызов, не через общий shell-инструмент). `psutil` имеет смысл только если свой код окажется длиннее и хрупче самой библиотеки.

| Инструмент | Вход | Выход | Опасность | Подтверждение | Когда |
| --- | --- | --- | --- | --- | --- |
| `process_info` | необязательный фильтр имени | pid, имя, короткие сведения, без убийства процесса | none | нет | P1 |
| `resource_info` | пусто | загрузка CPU, занятая RAM, при возможности GPU | none | нет | P1 |

Эти чтения используются и как проверка: «приложение запущено» смотрит в список процессов, а не в код возврата `Popen`.

### Оболочка

`shell.execute_command` — P1, после подтверждения в интерфейсе.

Вход: `command`, `cwd` внутри файловых корней, `timeout_sec` с жёстким потолком. Выход: код возврата, обрезанные stdout и stderr, `verified` только если задача отдельно описала, что считать успехом. Сам по себе нулевой код — `verified: null`.

Политика:

- нет общего разрешения без спроса;
- чтение вроде `Get-Process`, `Get-Date`, `dir` внутри корней может быть отдельными инструментами `process_info` / `list_files`, а не произвольной строкой shell;
- любая другая команда — `high` и подтверждение;
- безусловный запрет, даже после согласия в диалоге: форматирование диска, удаление корня диска, создание пользователей, правка реестра запуска, выключение машины, скачивание кода и немедленный его запуск. Такие команды возвращают `denied` и до оболочки не доходят.

Таймаут убивает дерево процесса команды и возвращает `timeout`.

### Сеть

| Инструмент | Вход | Выход | Опасность | Подтверждение | Когда |
| --- | --- | --- | --- | --- | --- |
| `open_page` | `url` с http или https | факт, что браузер получил URL | low, пока это тот же `webbrowser.open`, что уже есть у `open_app` | нет на первом шаге, чтобы не сломать «открой сайт»; позже можно поднять до medium | P2 как явное имя, поведение уже частично есть |
| `web.search` | `query` | заголовки и ссылки | none, если это только чтение | нет | P2. Нужен конкретный источник поиска. Пока его нет, инструмент не добавляется «пустым» и не тащит новый пакет ради одного вызова |

Отправки сообщений и платежей в коде нет. Будущий инструмент такого рода помечается `high`, без подтверждения не регистрируется. В P0–P2 их не делать.

## Права

Один модуль `makosh/permissions.py`. Инструменты не решают подтверждение сами по себе: перед вызовом агент спрашивает политику.

```text
decide(tool, args, speaker) -> allow | confirm | deny
```

Решение зависит от имени инструмента и грубых свойств аргументов (удаление, `enter`, путь, команда из списка запрета), а не от формулировки пользователя.

Канал подтверждения — тот же websocket, второе сообщение, не новый сервер:

```text
сервер → клиент: {type: "confirm", id, tool, summary, danger}
клиент → сервер: {type: "confirm_result", id, allow}
```

Ожидание ограничено по времени. Молчание и обрыв сокета равны отказу. `POST /api/chat` опасный инструмент не выполняет: у этого входа нет живого вопроса пользователю, ответ объясняет, что нужно подтверждение в веб-странице.

В P0 `decide` для нынешних десяти инструментов возвращает `allow` (кроме уже существующих отказов вроде чужого пути и чужой клавиши). Неизвестное имя — `deny`. Так beta не меняется, а оболочка и удаление не смогут попасть в обход политики.

Сочетания `press_hotkey` с `win` имеет смысл перевести в `confirm` только после кнопок в `index.html`. До этого шага поведение клавиш не менять, но риск зафиксирован в текущей архитектуре.

## Память

Одна база `data/memory.sqlite`. Новые таблицы появляются миграцией `CREATE TABLE IF NOT EXISTS` в том же классе `Memory`.

### Короткая

Уже есть таблица `turns`. Добавляется журнал последних вызовов инструментов: имя, аргументы без секретов, результат, время. В prompt по-прежнему идут последние реплики и, коротко, несколько последних вызовов текущей задачи. Полные stdout в системный prompt не кладутся.

Текущая задача в P1 — строка в таблице `tasks`: цель, статус, id устройства, время. Статусы: `running`, `needs_confirm`, `verified`, `failed`, `stopped`. Пока задачи нет, `handle` работает как сейчас.

### Долгая

Таблица `facts` остаётся долгой памятью. Позже к ней добавляется необязательная колонка `kind`: `preference`, `device`, `project`, `fact`. Старые строки живут как `fact`. Отдельная база устройств не нужна: стабильные сведения («ноутбук зовут так-то») пишутся фактом, а живые сокеты остаются в `DeviceRegistry`.

`recall("")` из `handle` и сейчас подмешивает несколько последних фактов. Этого достаточно, пока фактов мало. Поиск по ключевым словам уже есть у инструмента `recall`.

### Эпизодическая

Новая таблица `episodes`: цель, краткие шаги, итог, ошибка, что помогло, время конца. Запись появляется, когда задача дошла до `verified` или `failed`, а не на каждый удачный `Popen`. В контекст попадает один-два последних эпизода по совпадению слов цели, не вся таблица.

### Векторный поиск

Сейчас не нужен. Объём — десятки реплик и единицы фактов, поиск `LIKE` их покрывает. Эмбеддинги имеют смысл только если появятся сотни фактов и перефраз стабильно не находится по ключам. До этого дешевле держать явные ключи (`editor`, `project:makosh`) и эпизоды текстом. Зависимость под векторную базу не добавлять заранее.

## Зрение

Текущий путь не заменяется. `capture_image`, `local_ocr`, `compact_jpeg`, лимит часа и отказ DeepSeek от картинок остаются.

Цепочка, которую стоит добавить поверх:

```text
событие (фраза пользователя, позже — явная команда «следи»)
  → снимок
  → уменьшение и сравнение с прошлым кадром в памяти процесса
  → если кадр почти тот же и это не прямой вопрос «что на экране», остановиться
  → иначе локальный OCR
  → облачная модель только если политика зрения разрешает и OCR не ответил на вопрос
  → структура {changed, ocr, description, used_cloud}
```

Прямой запрос пользователя «посмотри экран» по-прежнему делает OCR сразу. Сравнение кадров отсекает повторные облачные вызовы и будущий опрос, а не первый ответ человеку.

`RapidOCR` стоит держать одним экземпляром на процесс: сейчас движок создаётся на каждый `look_screen`.

Постоянный наблюдатель экрана по умолчанию выключен. Он видит всё, что на мониторе, и грузит CPU. Включать его отдельной настройкой не раньше P2, когда сравнение кадров уже умеет сказать «ничего не изменилось» без модели.

Облачный JPEG по-прежнему ограничен `VISION_MAX_PER_HOUR`. Лимит лучше писать в SQLite, чтобы рестарт его не обнулял. Это маленькое изменение `vision.py`, не новый сервис.

Инструмент `screenshot` отдаёт структуру и локальный файл превью. В модель кадр попадает только через уже существующую ветку `look_screen` / vision.

## Model router

P0 выносит в `makosh/llm.py` тот клиент, который сегодня живёт в `Agent.__init__`.

- DeepSeek API: тот же модуль, другие `OPENAI_BASE_URL` и `OPENAI_MODEL`. Картинки выключены флагом возможностей, не проверкой подстроки по всему агенту.
- Другой API и локальная модель с OpenAI-совместимым сервером: те же две переменные. Отдельный класс не пишется.
- DeepSeek CDP: не реализация P0. Скрипт `scripts/start-deepseek-edge.ps1` остаётся ручным запуском страницы. Адаптер CDP имел бы смысл только как эксперимент P3: у страницы нет надёжных tool calls, вёрстка ломает разбор ответа, сессия живёт в профиле браузера. Если адаптер когда-нибудь появится, он реализует тот же `complete()` и сам объявит `supports_tools() = false`, чтобы агент не ждал структурированных вызовов.

Пока ключ пуст, поведение сохранить: понятный ответ, что облачная модель выключена. Локальные команды без модели в P0 не обещать.

Вызов `complete` увести с event loop через `asyncio.to_thread`, когда появится шов. Это убирает зависание телефона на время ответа модели и не требует нового HTTP-клиента.

## Несколько устройств

`MAKOSH_PEERS` в репозитории нет и для целевой схемы не обязателен. Сетка равных узлов размажет память и права.

Сейчас хаб и есть единственный мозг. Телефон и браузер на этом ПК — клиенты `DeviceRegistry`. Действия мыши, экрана и файлов выполняются на машине, где запущен процесс.

Целевая схема:

```text
Makosh Core (этот процесс на основном ПК)
   ├── браузер этого ПК
   ├── браузер телефона
   └── позже процесс-узел на ноутбуке
```

Узел ноутбука — не второй агент. В hello он сообщает `kind: laptop` и короткий список способностей (`screenshot`, `open_app`, …). Хаб, если задача явно про ноутбук, шлёт `{type: "tool", id, name, args}` в его сокет и ждёт `{type: "tool_result"}`. Права считает хаб до отправки. Результаты пишет хаб в ту же память.

Пока такого hello нет, ноутбук может только открыть ту же веб-страницу и говорить с агентом основного ПК. Это уже возможно в текущей сети и не требует нового протокола.

Обнаружение в LAN, mDNS и список пиров не входят в P0. Адрес хаба пользователь открывает сам, как сейчас.

Исправление гонки одного `device_id` при переподключении — часть P1 надёжности узлов: `drop` не должен удалять сокет, если в реестре уже другое соединение.

## Надёжность цикла

Для задачи с побочным эффектом цель такая:

```text
observe → plan → act → observe → verify → finish
```

P0 вводит это только для `open_app`: после запуска ещё раз смотрит, появился ли процесс. В ответ модели попадает свидетельство. Фраза пользователю не утверждает, что окно перед ним, если проверки не было.

P1 записывает задачу и проходит статусы. `finish` ставится при `verified`, либо агент говорит, что проверка не удалась. Исчерпание шести кругов помечает задачу `stopped`, а не успешным «Готово.». Пустой текст модели больше не подменяется словом «Готово.», если в этом ходе были инструменты с `verified != true`.

Подтверждение — развилка перед `act`, не после. Отказ пользователя завершает шаг как `failed` без вызова инструмента.

Повторная проверка — второй вызов дешёвого инструмента (`process_info`, `list_files`, OCR), а не второй запуск того же действия.

## Дорожная карта

### P0 — надёжное ядро, beta на месте

Нужно, чтобы новые опасные инструменты было куда вставлять, и чтобы агент не врал себе об успехе запуска.

1. Реестр инструментов вокруг уже существующих функций.
2. Политика прав: текущие инструменты разрешены как сейчас, неизвестные запрещены.
3. Шов модели `makosh/llm.py` с теми же переменными `.env`.
4. Ошибка модели и битый JSON аргументов возвращают текст пользователю и не рвут websocket.
5. Журнал tool calls в том же SQLite; сборка prompt не раздувается всем stdout.
6. `open_app` отличает «процесс создан» от «процесс не найден» через `verified`.
7. Контракты `/ws`, `/api/chat`, `/api/health` и страница без смены сценария.

В P0 не входят оболочка, удаление, мышь, CDP, наблюдатель экрана и узел ноутбука.

### P1 — полезный помощник

1. Канал `confirm` в websocket и кнопки на странице.
2. `read_file` и `search_files` без подтверждения, внутри корней.
3. `write_file`, `delete_file`, `delete_folder` только через подтверждение.
4. `execute_command` только через подтверждение и список безусловных запретов; нулевой код сам по себе задачу не закрывает.
5. `process_info` и `resource_info`.
6. `close_application` с подтверждением, `focus_window` без.
7. Кириллица в наборе текста через буфер обмена, с записью, какое окно было в фокусе.
8. Кэш движка OCR, сравнение кадров перед облачным vision, лимит часа в SQLite.
9. Задачи и эпизоды в том же SQLite. Контекст получает цель и пару эпизодов, не всю историю инструментов.
10. Колонка `kind` у фактов.
11. Вызов модели вне event loop.
12. Протокол узла: ноутбук объявляет способности, хаб делегирует ему локальный инструмент.
13. Починка `drop` при переподключении с тем же id.

Голос браузера остаётся. Серверный `edge-tts` подключать только если на телефоне `speechSynthesis` реально молчит: пакет уже объявлен, но сейчас не используется.

### P2 — улучшения

- `mouse` с подтверждением и кадром после клика.
- Явное имя `open_page`.
- Поиск в вебе, когда выбран конкретный источник без лишней инфраструктуры.
- Сужение файловых корней до Desktop, Downloads, Documents и `data` отдельным решением, с настройкой, если понадобится текущий широкий доступ к домашнему каталогу.
- Короткоживущая выдача файла без постоянного токена в query.
- Разделение журнала по устройству, если общий диалог начнёт мешать.
- Таймаут и простая частота на `/api/chat` и `/ws`.
- Снимок выбранного монитора, не только индекса 1.
- Наблюдатель экрана выключен настройкой и молчит, пока кадр не изменился.
- Поток текста ответа, если он понадобится голосу.

### P3 — эксперименты

- Адаптер CDP к странице DeepSeek за тем же `complete()`, выключенный по умолчанию.
- Инструменты сообщений и платежей, каждый `high`.
- Векторный поиск по фактам и эпизодам, если `LIKE` перестанет находить нужное.
- Постоянный присмотр за экраном как основной режим.

Локальная OpenAI-совместимая модель в этот список не входит: для неё достаточно URL в `.env`, когда шов из P0 уже есть.

### M2. Реестр

Цель: `TOOL_SCHEMAS` и `_run_tool` читают один реестр. Набор имён тот же, функции те же.

Готово, когда тест вызывает каждое существующее имя и получает тот же класс результата, что прямой вызов функции. Страница и маршруты не меняются.

### M3. Политика

Цель: `decide()` перед исполнением. Для текущих инструментов результат `allow`. Неизвестное имя — `deny` и строка модели, без исключения наружу.

Готово, когда тест на неизвестный инструмент не создаёт файл и не запускает процесс.

### M4. Ошибки модели

WebSocket и битый JSON аргументов уже закрыты в M1. Не повторять эту работу.

Остаток шага: `POST /api/chat` при сбое модели сейчас отвечает ошибкой сервера, а не той же короткой фразой, что WebSocket. Менять это только если понадобится одинаковое поведение обоих входов. Сокет страницы уже переживает исключение.

### M5. Шов LLM

Цель: `Agent` получает объект с `complete` и флагами возможностей. Прод-реализация — текущий SDK. Пустой ключ ведёт себя как сейчас.

Готово, когда смена base URL по-прежнему только в `.env`, а тест агента проходит на фейковом `complete` без сети.

Цель: таблица вызовов в `memory.sqlite`. В модель уходит короткая сводка, не полный дамп.

Готово, когда после хода с инструментом в базе есть запись, `recall` фактов работает по-старому, а число реплик в prompt не выросло на весь вывод инструмента.

Цель: `execute_command` с таймаутом, подтверждением и безусловным запретом опасных классов команд.

Готово, когда запрещённая команда не стартует даже при `allow`, а разрешённая после подтверждения возвращает код и обрезки потоков с `verified: null`.

Цель: `process_info`, `resource_info`, `focus_window`, `close_application` (закрытие только с подтверждением).

Готово, когда «запусти и проверь» может опереться на `process_info`, а закрытие без подтверждения не посылает сигнал процессу.

Цель: один экземпляр OCR, сравнение уменьшенного кадра, лимит часа в SQLite. Прямой `look_screen` с OCR не ломается. Облако по-прежнему не вызывается для DeepSeek и не превышает лимит.

Готово, когда повторный почти тот же кадр в режиме проверки не зовёт облако, а явная просьба посмотреть экран всё ещё возвращает OCR.

### M14. Задачи и эпизоды

Цель: таблица задач и запись эпизода в конце хода с инструментами. Пустой ответ модели при неподтверждённом эффекте не заменяется на «Готово.».

Готово, когда оборванный по лимиту кругов ход виден как `stopped`, а успешный проверенный `open_app` — как эпизод с `verified`.

### M15. Модель не блокирует хаб

Цель: `complete` в `asyncio.to_thread`.

Готово, когда во время искусственно долгого `complete` второй клиент успевает получить `hello` или health не висит на том же ожидании дольше малого таймаута теста.

### M16. Узел ноутбука

Цель: hello со списком способностей и делегирование одного локального инструмента. Память и права остаются на хабе.

Готово, когда фейковый сокет ноутбука получает `tool` только после `allow`, а результат попадает в журнал хаба. Телефон без списка способностей работает как раньше.

## Риски

| Риск | Почему важен | Как ограничить |
| --- | --- | --- |
| Подтверждения сломают голос | каждый клик «да» убивает ощущение помощника | не переводить старые инструменты в `confirm`, пока кнопки не готовы; спрашивать только запись, удаление, оболочку, закрытие, опасные клавиши |
| Ложное «Готово» | пустой ответ модели и успешный `Popen` уже выглядят как успех | `verified` и запрет подмены фразы в M7 и M14 |
| Широкий домашний каталог | `list_files` и `send_file` могут унести секреты профиля на телефон | не менять корни молча в P0; сужение — отдельное решение P2 |
| Загрузка в inbox | `device_id` и имя файла не привязаны к каталогу так же, как скачивание | починить проверкой resolved-пути в том шаге, где трогаем файлы |
| `cmd` в списке бинарников | не описан в README, но запускается | убрать из списка отдельным маленьким шагом после теста, который фиксирует белый список; это закрытие дыры, не сценарий из README |
| `win` в горячих клавишах | сочетание может увести сессию с рабочего стола | подтверждение после M8, не раньше |
| Набор русского текста | `typewrite` ненадёжен для кириллицы | буфер обмена в P1, с проверкой окна |
| Общий диалог | телефон и ПК пишут в одни `turns` | оставить общим в P0: для одного хозяина это общая память; дробить в P2, если задачи начнут путаться |
| Гонка сокета | старый `finally` удаляет новый `device_id` | M16, до этого не строить на реестре долгие ожидания подтверждения без проверки, что сокет тот же |
| Блокирующий SDK | чат держит весь процесс | M15, без смены провайдера |
| OCR на каждый взгляд | задержка и CPU | один экземпляр движка в M13 |
| CDP | хрупкий разбор сайта и обход tool calling | не делать рабочим backend |
| Лишние абстракции | планировщик, шина и векторная база спрячут простой цикл | классы только из таблицы Agent Core |
| Права инструментов равны правам пользователя Windows | агент может всё, что может учётка | подтверждение и запреты — последний рубеж в приложении, не песочница ОС |

## Как проверять

Автотестов сейчас нет. Их стоит добавить с M1, без требования живого ключа и без снимка реального рабочего стола в CI.

- Память: upsert факта, лимит реплик, позже журнал инструментов и эпизод.
- Пути: файл внутри корня, путь снаружи, разбор upload/inbox так, чтобы скачивание и запись не выходили из `data/inbox`.
- Права: `allow` для `open_app("блокнот")`, `deny` для неизвестного имени и для запрещённой команды оболочки даже при согласии.
- Реестр: каждое старое имя резолвится, схема содержит обязательные поля.
- Цикл агента: фейковый `complete` возвращает tool call, затем текст; исключение backend не роняет реестр устройств; отсутствие `verified` не превращается в успех задачи.
- Зрение: счётчик лимита и сравнение двух заранее заданных картинок. Реальный монитор в юнит-тест не входит.
- Узел: фейковый websocket получает делегирование только после разрешения.

Ручная проверка после шагов, которые трогают страницу или ПК:

- страница на `http://127.0.0.1:8787`, токен, текст, ответ;
- кнопка голоса в Chrome или Edge, если шаг трогал `index.html`;
- телефон в той же сети открывает ту же страницу и получает `file`, если шаг трогал inbox;
- «открой блокнот» заканчивается видимым окном, и ответ агента совпадает с фактом окна;
- опасный шаг с подтверждением: отмена не меняет диск, согласие меняет только названный путь.

Шаг не считается законченным, если ради него перестал открываться health или чат без API-ключа.
