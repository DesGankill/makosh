# Текущая архитектура Makosh

Снимок кода на 29 сентября 2026. Версия пакета `0.1.0` (`makosh/__init__.py`). Коммитов в `master` ещё нет. Это описание работающего дерева, а не целевой схемы.

Makosh сейчас — один Python-процесс на Windows. Он отдаёт веб-страницу, принимает текст и голос из браузера, вызывает OpenAI-совместимую модель и выполняет несколько локальных действий на том же ПК. Отдельных сервисов, очередей и баз, кроме одного SQLite-файла, нет.


Каталога `tests/` нет. Каталог `data/` в gitignore: туда попадают `memory.sqlite` и `inbox/`.

| Зависимость | Где используется |
| --- | --- |
| fastapi, uvicorn | `makosh/hub.py`, `makosh/__main__.py` |
| python-dotenv | `makosh/config.py` |
| openai | `makosh/agent.py` |
| python-multipart | загрузка файла в `hub.upload` |

| httpx | объявлена в `requirements.txt`, прямых вызовов в коде нет |

Синтаксис `str | None` и `list[dict]` требует Python 3.10+.

## Компоненты

### Точка входа

`makosh/__main__.py`

Запускает uvicorn с приложением `makosh.hub:app`, хост и порт из конфигурации, `reload=False`. Других процессов этот модуль не поднимает.

### Конфигурация

`makosh/config.py`, шаблон `.env.example`

При импорте читает `.env` из корня репозитория. Экспортирует константы, не объект настроек:

- сеть: `MAKOSH_HOST` (по умолчанию `0.0.0.0`), `MAKOSH_PORT` (`8787`), `MAKOSH_TOKEN` (по умолчанию `change-me-now`), `MAKOSH_DEVICE_NAME` (`PC`);
- модель: `OPENAI_API_KEY`, `OPENAI_BASE_URL` (`https://openrouter.ai/api/v1`), `OPENAI_MODEL`, `VISION_MODEL`;
- зрение: `VISION_MAX_PER_HOUR` (`6`), `VISION_MAX_WIDTH` (`768`);
- пути: `data/`, `data/inbox/`, `data/memory.sqlite`;
- белый список приложений `ALLOWED_APPS`: проводник, блокнот, калькулятор, браузер.

Переменной `MAKOSH_PEERS` в конфигурации нет.

### HTTP и WebSocket

`makosh/hub.py`

Создаёт `FastAPI`, один экземпляр `Memory`, один `DeviceRegistry`, один `Agent`. Раздаёт статику из `makosh/static` с корня `/` после объявления API-маршрутов.

| Маршрут | Назначение |
| --- | --- |
| `GET /api/health` | без токена, имя этого хаба |
| `POST /api/chat` | текст → `agent.handle`, заголовок `x-makosh-token` |
| `POST /api/upload/{device_id}` | сохранить загруженный файл в inbox |
| `GET /api/inbox/{device_id}/{name}?token=` | скачать файл |
| `WS /ws` | регистрация устройства и чат |
| `/` | `static/index.html` и остальная статика |

Проверка токена — сравнение строки с `config.TOKEN` (`_check` и такая же проверка в websocket и в выдаче файла).

### Веб-клиент

`makosh/static/index.html`

Одна страница без сборки. Хранит токен, имя и `device_id` в `localStorage`. Подключается к `/ws`, шлёт `{type: "chat", text, speak: true}`. Голос на вход — `SpeechRecognition` / `webkitSpeechRecognition`, язык `ru-RU`. Голос на выход — `speechSynthesis`, тоже `ru-RU`. Сообщение `{type: "file"}` показывает ссылку на скачивание с токеном в query. При обрыве сокета переподключается через 1,5 с. Поле `kind` выставляется как `android` или `pc` по user agent.

Страница не вызывает `POST /api/chat` и `POST /api/upload`.

### Агент

`makosh/agent.py`, класс `Agent`

Единственный оркестратор. В конструктор передаются память, `devices.list_text` и async-функция `send_file` из хаба.

`handle(text, speaker)`:

1. пишет реплику пользователя в SQLite с префиксом `[speaker]`;
2. если нет API-ключа, возвращает фиксированный текст и тоже пишет его в историю;
3. собирает сообщения: системный промпт, до 8 фактов, последние 16 реплик;
4. до 6 раз вызывает `chat.completions.create` с `TOOL_SCHEMAS` и `tool_choice="auto"`;
5. без tool calls возвращает текст модели или «Готово.»;
6. с tool calls дописывает assistant-сообщение и результаты инструментов, затем снова зовёт модель;
7. после 6 кругов останавливается фразой про слишком длинную цепочку.

Исполнение инструмента — цепочка `if/elif` в `_run_tool`. Схемы для модели лежат в `TOOL_SCHEMAS` в том же файле. Отдельного реестра, планировщика и менеджера прав нет.

Список имён, которые модель может вызвать: `remember`, `recall`, `list_devices`, `list_files`, `send_file`, `look_screen`, `open_app`, `open_path`, `type_text`, `press_hotkey`.

### Инструменты ПК

`makosh/tools.py`

Импорт модуля включает `pyautogui.FAILSAFE = True`.

| Функция | Поведение |
| --- | --- |
| `list_files` | до 80 имён в каталоге после проверки пути |
| `open_path` | `os.startfile` |
| `open_app` | белый список имён и бинарников, иначе отказ; URL открывает `webbrowser` |
| `type_text` | `pyautogui.typewrite` в текущее активное окно |
| `press_hotkey` | `pyautogui.hotkey` по короткому списку клавиш |
| `copy_into_inbox` | копия файла в `data/inbox/<device_id>/` |

`_safe_path` разрешает путь, если он внутри одной из `SAFE_ROOTS`: домашний каталог пользователя, `data/`, Desktop, Downloads, Documents. Домашний каталог покрывает три остальные пользовательские папки и почти весь профиль.

`open_app` дополнительно разрешает бинарники `explorer`, `notepad`, `calc`, `mspaint`, `cmd`, даже если их нет в `ALLOWED_APPS`. Любая строка, которая начинается с `http://` или `https://`, открывается в браузере. Имена из README («блокнот», «калькулятор», «проводник» через ключ «проводника», «браузер») завязаны на `config.ALLOWED_APPS`.

Проверки, что окно реально появилось, нет. Успешный `Popen` или `startfile` сразу считается результатом.

### Память

`makosh/memory.py`, класс `Memory`

Один SQLite, `check_same_thread=False`, без явной блокировки.

Таблица `facts`: уникальный `key`, `value`, `updated_at`. `remember` делает upsert. `recall` ищет `LIKE` по ключу и значению, лимит 8. Пустой или несовпавший запрос возвращает 8 последних фактов, а не пустой результат.

Таблица `turns`: `role`, `content`, `created_at`. Хранятся последние 40 строк. В модель уходят последние 16, в хронологическом порядке.

Отдельных таблиц задач, эпизодов и журнала инструментов нет. Вызовы инструментов в `turns` не пишутся: в истории остаётся только исходная реплика и итоговый ответ.

### Устройства

`makosh/devices.py`

`Device` — id, имя, kind, websocket, `last_seen`. `last_seen` ставится при создании и дальше не обновляется.

`DeviceRegistry` держит словарь в памяти процесса. `find` сравнивает id, имя и kind, затем короткие вхождения, затем алиасы «телефон / андроид / phone → android» и «пк / комп / компьютер → pc». `send` пишет JSON в сокет устройства. После рестарта список пуст, пока клиенты не подключатся снова.

Повторная регистрация с тем же id затирает сокет. `finally` старого соединения вызывает `drop` и может снять уже новое соединение.

### Зрение

`makosh/vision.py` и ветка `_look_screen` в `makosh/agent.py`

- `capture_image` снимает `mss` монитор с индексом 1 (основной экран, не виртуальный стол и не второй монитор).
- `local_ocr` каждый вызов создаёт новый `RapidOCR()` и склеивает распознанные строки.
- `compact_jpeg` уменьшает ширину до `VISION_MAX_WIDTH` и сохраняет JPEG quality 45. Нужен только для облака.
- `save_preview` ниоткуда не вызывается.
- Счётчик облачных вызовов — `deque` в памяти процесса, окно 3600 секунд. Рестарт обнуляет лимит.

`look_screen` всегда сначала делает снимок и OCR.

- `mode=ocr`: вернуть текст, обрезанный до 4000 символов, либо фразу, что OCR пуст и облако для картинок недоступно.
- `mode=vision`, если в `OPENAI_BASE_URL` или `VISION_MODEL` есть подстрока `deepseek`: облако не вызывается, возвращается OCR.
- иначе `consume_vision_slot()`; при отказе — OCR и сообщение о лимите;
- иначе снимок уходит в `VISION_MODEL` как data-URL JPEG вместе с куском OCR.

Наблюдателя экрана, сравнения кадров и очереди «изменилось → решить, звать ли модель» нет. Снимок уходит в модель только когда модель сама выбрала `look_screen` с `mode=vision` и проверки выше это разрешили.

### Голос

Вход и выход живут в браузере: `makosh/static/index.html`, функции `speak` и `SpeechRecognition`.

Сервер голос не синтезирует и аудио не хранит. Флаг `speak` учитывает только websocket-ответ. `POST /api/chat` принимает `speak` в `ChatBody` и игнорирует его. Пакет `edge-tts` к этому пути не подключён.

### Скрипт Edge

`scripts/start-deepseek-edge.ps1`

Ищет `msedge.exe`, создаёт профиль `%LOCALAPPDATA%\Makosh\edge-deepseek` и запускает Edge с `--remote-debugging-port=9222` и страницей `https://chat.deepseek.com`. Дальше скрипт завершается. Python к порту 9222 не подключается, DOM чата не читает и сообщения туда не пишет.

## Зависимости между модулями

```
браузер (index.html)
    │  WS /ws , реже POST /api/chat
    ▼
hub.py ── создаёт ── Memory, DeviceRegistry, Agent
    │                    │           │
    │                    │           ├── config.py
    │                    │           ├── memory.py
    │                    │           ├── vision.py
    │                    │           └── tools.py
    │                    │
    └── send_file ───────┘ devices.py
              копия через tools.copy_into_inbox
              уведомление через websocket устройства
```

`agent.py` импортирует `openai` и сам создаёт клиент. Хаб не знает набор инструментов. Инструменты не знают про модель. Память не знает про устройства. Цикл такой один: хаб передаёт агенту замыкание `send_file`, потому что отправка файла должна и скопировать файл, и толкнуть чужой сокет.

## Точки входа

1. `python -m makosh` — обычный запуск хаба.
2. `GET /api/health` — проверка, что процесс жив.
3. `WS /ws` — путь, которым пользуется страница.
4. `POST /api/chat` — тот же `Agent.handle` без голоса и без сокета устройства.
5. `POST /api/upload/...` и `GET /api/inbox/...` — файлы, страница загрузку не показывает.
6. `scripts/start-deepseek-edge.ps1` — ручной запуск браузера, не вход в агента.

## Поток: пользователь → модель → ответ

1. Пользователь пишет текст или диктует его в браузере. Распознавание речи заканчивается в `index.html`, на сервер уходит уже строка.
2. Сокет шлёт `{type: "chat", text, speak: true}` после hello с токеном.
3. `hub.ws` вызывает `agent.handle(text, name)`.
4. `Memory.add_turn` сохраняет реплику.
5. `Agent.handle` собирает prompt и синхронно вызывает `OpenAI.chat.completions.create`. Вызов блокирует event loop единственного процесса.
6. Если модель вернула текст, он пишется в `turns` и уходит клиенту как `{type: "reply", text, speak}`.
7. Браузер рисует абзац и, если `speak` истинно, произносит его через `speechSynthesis`.

Тот же `handle` обслуживает `POST /api/chat`. Ответ там — JSON `{"reply": "..."}` без TTS.

Модель одна на текст и на инструменты: `config.MODEL`. Отдельная модель есть только у облачного кадра: `config.VISION_MODEL`. Выбор «какой backend» — это значения `OPENAI_BASE_URL` и `OPENAI_MODEL` на старте процесса. Ветвления по провайдеру внутри цикла нет, кроме отказа от картинок при подстроке `deepseek`.

## Поток: пользователь → инструмент → модель → ответ

1. Модель возвращает `tool_calls`.
2. Аргументы парсятся через `json.loads` в цикле `handle`, ещё до `_run_tool`.
3. `_run_tool` сопоставляет имя и вызывает память, реестр устройств, `tools.py` или `_look_screen`.
4. Любое исключение внутри `_run_tool` превращается в строку `Ошибка инструмента ...` и отдаётся модели как `role: tool`.
5. Модель получает эту строку и либо отвечает пользователю, либо зовёт следующий инструмент.
6. Промежуточные вызовы в SQLite не сохраняются. Клиент видит только финальный текст.

Подтверждения в этом цикле нет. Отдельного наблюдения после действия нет: строка «Запустил notepad» и есть результат.

Пример «открой блокнот»:

`open_app` → ключ находится в `ALLOWED_APPS` → `subprocess.Popen("notepad")` → строка «Запустил notepad» → модель формулирует ответ. Процесс и окно повторно не проверяются.

Пример «посмотри экран»:

`look_screen` → `capture_image` → `local_ocr` → при `mode=ocr` текст OCR возвращается модели без картинки. Облачный JPEG возможен только в ветке `mode=vision` и только если провайдер не опознан как DeepSeek и лимит часа не исчерпан.

Пример «отправь файл на телефон»:

`send_file` в хабе ищет устройство через `DeviceRegistry.find`. Если его нет, файл копируется в `inbox/unclaimed`. Если есть, копия кладётся в `inbox/<device_id>/`, в сокет телефона уходит `{type: "file", name, url}`, модель получает текст со ссылкой.

## Где хранится состояние

| Состояние | Место | Срок жизни |
| --- | --- | --- |
| Факты и реплики диалога | `data/memory.sqlite` | до удаления файла; реплики обрезаются до 40 |
| Подключённые устройства | словарь в `DeviceRegistry` | до рестарта или обрыва сокета |
| Лимит облачного зрения | `deque` в `vision.py` | до рестарта |
| Клиент OpenAI | поле `Agent._client` | до рестарта |
| Токен, имя, id браузера | `localStorage` | на этом браузере |
| Входящие файлы | `data/inbox/` | пока файлы не удалят вручную |
| Профиль Edge для DeepSeek | `%LOCALAPPDATA%\Makosh\edge-deepseek` | вне репозитория, скриптом только создаётся |
| Текущая задача, план, права, кадр для сравнения | нет | — |

Один журнал `turns` общий для всех устройств. Имя говорящего только префикс в тексте.

## DeepSeek

**API.** Отдельного клиента DeepSeek нет. Тот же `OpenAI(...)` в `Agent.__init__` ходит туда, куда указывает `OPENAI_BASE_URL`. Чтобы говорить с API DeepSeek, достаточно поменять URL и модель в `.env`. Код при этом отключает отправку изображений, если в URL или имени vision-модели встречается `deepseek`. Tool calling используется в том виде, в каком его отдаёт OpenAI SDK; отдельной адаптации протокола нет.

**CDP.** Backend отсутствует. Есть только запуск Edge с портом отладки. Сессии чата, селекторов, чтения ответа и tool calling через страницу в репозитории нет.

## Ошибки

- Исключение инструмента ловится в `_run_tool` и становится текстом для модели.
- `chat.completions.create` и `json.loads(tc.function.arguments)` не обёрнуты. Исключение выходит из `handle`. В websocket его ловит только общий выход из цикла: соединение закрывается в `finally`, клиент видит обрыв и переподключается. Отдельного `{type: "error"}` на сбой модели нет. Реплика пользователя при этом уже записана, ответ ассистента — нет.
- Пустой `content` без tool calls заменяется на «Готово.».
- Сеть модели, таймаут и число повторов в коде не заданы: остаются умолчания SDK.
- `open_app` / `open_path` не отличают «процесс создан» от «пользователь видит окно».
- Неизвестный инструмент возвращает строку, а не исключение.

## Безопасность

Процесс слушает все интерфейсы и выполняет действия от имени вошедшего в Windows пользователя.

- Общий секрет сравнивается как обычная строка. Значение по умолчанию — `change-me-now`.
- Страница и health открыты без токена. Токен нужен для чата, upload и скачивания.
- Ссылка на файл несёт токен в query string. Копия токена лежит в `localStorage`.
- TLS нет.
- Скачивание из inbox проверяет, что resolved-путь остаётся внутри `data/inbox`. Загрузка так не проверяет: `device_id` и `file.filename` присоединяются к пути как есть.
- `_safe_path` пускает почти весь домашний каталог, включая каталоги вроде `.ssh`, если они лежат в профиле. `list_files` и `send_file` могут прочитать и переслать такой файл на подключённый браузер.
- `cmd` входит в фактический список запускаемых программ. В README его нет.
- `press_hotkey` разрешает сочетания из своего списка, среди них есть `win` и `l`.
- `type_text` печатает в то окно, которое сейчас в фокусе, без проверки заголовка.
- Подтверждения опасного действия нет.
- Единственный аварийный ограничитель мыши/клавиатуры — failsafe pyautogui: курсор в угол экрана прерывает pyautogui.

## Точки расширения, которые уже есть

- Новое имя инструмента: запись в `TOOL_SCHEMAS` и ветка в `_run_tool`. Оба места в `agent.py`.
- Новое безопасное приложение: `ALLOWED_APPS` и множество `allowed_bins` в `open_app`.
- Другой OpenAI-совместимый хост: `.env`, без правок цикла.
- Новый kind устройства: произвольная строка в hello; поиск знает только текущие алиасы.
- Факты: любые пары key/value через инструмент `remember`.
- Смена системного промпта: константа `SYSTEM`.

Этого мало для оболочки, удаления файлов, подтверждений и второго компьютера: соответствующих веток и протокола в коде нет.

## Узкие места

- Один процесс и синхронный вызов модели блокируют и чат, и доставку файла на телефон на время ответа LLM и OCR.
- `RapidOCR()` создаётся на каждый `look_screen`, вместе с загрузкой ONNX.
- Общий диалог на все устройства смешивает задачи телефона и ПК.
- Шесть кругов инструментов не равны плану с проверкой. Остановка по счётчику забывает промежуточные результаты для пользователя, они есть только в оперативном списке `messages`.
- SQLite без блокировки при двух одновременных чатах.
- Переподключение с тем же `device_id` может снять новое соединение из `finally` старого.
- Зрение привязано к одному монитору и к явному выбору модели. Сравнения кадров нет, поэтому любой будущий «постоянный присмотр» сейчас означал бы новый OCR или новый JPEG на каждый тик.
- Запуск приложения не проверяется. Для агента это главный смысловой разрыв: команда завершилась, а цель могла не наступить.
- CDP-скрипт не является запасным LLM-путём. Пока API-ключ пуст, агент отвечает одной заготовленной фразой и локальные команды тоже не разбирает.
- `pyautogui.typewrite` рассчитан на латинские символы. Русская диктовка в активное окно этим инструментом не набирается надёжно.
